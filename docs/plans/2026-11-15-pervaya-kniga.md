# Все главы первой книги Берна в приложении — план

Цель: в приложении есть введение, все 18 глав книги «Игры, в которые играют люди» и разбор
каждой игры из неё; каждое утверждение, ответ теста и карточка сверены с текстом издания.
Подход: сначала источник и проверяльщики, потом правка уже готовых глав, потом главы по
одному конвейеру. Главу пишет один исполнитель, сверяет с книгой другой, который её не писал.
После первых трёх глав и после первой главы с играми работа встаёт до вычитки владельцем.
Постановка: сообщения владельца в сессии 15.11.2026: «план, чтобы сделать по всем главам,
главное качественно»; источник — файл книги от владельца; объём — сначала первая книга.

## Общие ограничения

- Источник правды — текст издания владельца в `source/`. Чего нет в тексте главы, того нет
  в приложении. Память о книге источником не считается.
- `source/` в git не попадает: там файл книги, тексты глав, листы фактов и отчёты сверки.
- Конспект пересказывает своими словами. Цитата из книги не длиннее одной фразы. Конспект
  главы без строк «Проще» не длиннее четверти её текста (30% для глав короче 10 тыс.
  знаков), вместе с «Проще» — не длиннее 40%. Это опора для повторения, а не замена книги.
- Термины и названия глав и игр — как в издании владельца, по `docs/glossary.md`. Один
  термин называется одним словом во всех главах.
- Обращение к читателю на «ты», без рода: ни «ты прочитала», ни «ты прочитал». Эталонные
  ответы от первого лица тоже без рода.
- Русский текст — по скиллу `antineyroslog`; сканер должен показать «сильных: 0».
- id карточек и письменных вопросов (`<глава>-c<N>`, `<глава>-w<N>`) не меняются и не
  переиспользуются: на них держится прогресс на телефоне.
- Один коммит на задачу. Пуш в `main` сразу выкладывает на https://envilope1337.github.io/bern/;
  пуш после каждой задачи одобрен вместе с этим планом.
- Субагента запускать по скиллу `agent-briefing`; сверку всегда делает отдельный агент на
  Opus, который не писал главу и не видел рассуждений автора.
- Перед записью файла проверки в `tools/` вызвать скилл `fast-tests`; перед коммитом с
  правкой `index.html` или `styles.css` — скилл `ui`.

### Состав главы

- Конспект: все разделы главы в порядке книги. Каждый термин главы — блок с определением
  по книге и строкой «Проще». Примеры Берна своими словами. Схема там, где в книге рисунок.
- Тест: вопросов столько, сколько в главе проверяемых мыслей, от 4 до 12; в главах с
  играми не меньше двух на игру. Не меньше половины вопросов — ситуации из жизни
  (`kind: 'case'`), остальные на знание (`kind: 'fact'`). Четыре варианта, верный один.
  Неверные правдоподобны и опровергаются текстом главы. Верный не выделяется длиной.
  У каждого неверного своё объяснение. Разбор добавляет причину, а не повторяет ответ.
- Вопрос не решается без книги. Неверный вариант — то, во что поверит невнимательный
  читатель: соседнее понятие главы, верное утверждение не к этому вопросу, житейская
  догадка в спокойном тоне. Слова «всегда», «только», «никак» и оговорки «может», «обычно»
  стоят в верных и неверных вариантах одинаково часто. Верный вариант не пересказывает
  условие. Условие и варианты одного вопроса не подсказывают ответ другого.
- Приёмы, которые выдержали прогон без книги: четыре варианта из одного закрытого ряда
  (четыре термина главы, четыре состояния Я, четыре числа одного вида); полная сетка два
  на два (два признака, все четыре сочетания); один синтаксис у всех четырёх вариантов;
  вопрос «что это по Берну», а не «прав ли герой»; житейская догадка верна примерно в
  четверти вопросов. Неполная сетка, пара похожих вариантов при двух пустых, «или» или
  пример только у верного — выдают ответ. Сюжет, который показывает понятие, не брак.
  Подробный разбор с примерами: `source/facts/nobook-rules.md`.
- Глава с играми: на каждую игру раздел конспекта и в нём блок `{ game: {...} }`. Поля:
  `name` (как в заголовке книги, без кавычек) и `thesis` обязательны; `abbr`, если книга
  сама сокращает название; строки `aim`, `roles`, `dynamics`, `social`, `psychological`,
  `antithesis`, `related`; списки строк `examples`, `moves`, `advantages`. Поле ставится,
  только если книга даёт это для данной игры: недостающие пункты анализа не выдумывать.
  В тесте на каждую игру не меньше двух вопросов с пометкой `game: '<название>'`, плюс
  до двух общих вопросов; в таких главах тест бывает до 16 вопросов. На каждую игру есть
  карточка с её названием.
- Письменные вопросы: 2–3. Один на объяснение своими словами, один на пример из жизни,
  один на сравнение понятий. К каждому эталон и 3–5 пунктов проверки.
- Карточки: один факт на карточку, ответ до 200 знаков, на каждый термин есть карточка.

### Конвейер главы

1. Прочитать `source/text/<id>.txt` целиком и рисунки главы.
2. Лист фактов `source/facts/<id>.md`: термины, утверждения, примеры, имена, числа. У каждой
   строки место в тексте (раздел, абзац).
3. Написать `content/<id>.js` только по листу фактов.
4. `node tools/check-content.js` → «замечаний: 0».
5. `node tools/check-content.js --dump <файл>`, затем сканер `antineyroslog` → «сильных: 0».
6. Сверка: отдельный агент получает текст главы и `content/<id>.js`, возвращает расхождения
   строками `место в файле — что в приложении — что в книге`. Отчёт в `source/verify/<id>.md`.
   Каждое расхождение исправлено или отклонено с причиной в том же файле.
7. Решение теста вслепую, два прогона разными агентами. Вопросы без отметки верного ответа
   даёт `node tools/check-content.js --blind <id> <файл>`, сверку с ключом — `--grade`.
   - Без книги: агент видит только вопросы и по каждому называет, что подсказало ответ;
     его файл сверяет с ключом `node tools/grade-nobook.js <файл>`.
     Вопрос идёт на переделку, если ответ угадан по форме: по словам «всегда» и «только»,
     по осторожному тону, по нелепости остальных вариантов, по пересказу условия, по
     подсказке из соседнего вопроса. Ответ по знанию теории не считается.
   - С книгой: агент получает текст главы. Вопрос идёт на переделку, если его ответ не
     совпал с отмеченным или он счёл верными два варианта. Этот прогон идёт последним:
     правдоподобные неверные варианты проверяются на то, что книга их опровергает.
8. Строка в `content/files.js` и в `content/book.js`. `python tools/check_app.py` →
   «проблем нет». Новые схемы открыть на снимках 375.
9. Коммит, пуш, `python tools/check_app.py --base https://envilope1337.github.io/bern/` →
   «проблем нет». Отметка в этом файле.

## Что сломает живой пользователь

1. Глава обновилась, а карточки и ответы на телефоне обнулились — ожидает, что прогресс
   цел — id не меняются, проверка в задаче 3.
2. Телефон выгрузил вкладку посреди теста — ожидает продолжить с того же вопроса —
   проверка в задаче 7.
3. Вышла новая глава, а на телефоне старая версия — ожидает увидеть главу без
   переустановки и открыть её без сети после первой загрузки — проверка в задаче 5.
4. В главе шесть разборов игр подряд — ожидает сразу найти нужную игру — список игр в
   начале конспекта и сворачиваемые разборы, проверка в задаче 14.
5. Двойное нажатие на вариант ответа — ожидает, что ответ засчитан один раз — проверка
   в задаче 5.

## Решения по ходу

- План: листы фактов и отчёты сверки лежат в `source/`, не в `docs/` — в них цитаты из
  книги, а репозиторий публичный — если папка `source/` пропадёт, сверку не воспроизвести,
  поэтому проект должен жить в постоянной папке на диске.
- План: число вопросов привязано к содержанию главы, а не к восьми — короткие главы части
  III иначе пришлось бы добивать водой — тесты получатся разной длины.
- До плана, 15.11.2026: длина вариантов в 32 готовых вопросах выровнена по прямой просьбе
  владельца, коммит `a7af69e` — верный вариант был самым длинным в 24 вопросах из 32, стал
  в 1 — сверки с книгой эта правка не проходила, её закроет задача 8.
- До плана, 15.11.2026: готовые главы написаны словами другого перевода («структурирование
  времени», «времяпрепровождения») — у владельца перевод Грузберга («упорядочивание
  времени», «развлечения») — до задачи 8 термины в приложении расходятся с книгой.

- Задача 3: правило 7 считает объём конспекта дважды: без строк «Проще» — не больше 25%
  главы (30% для глав короче 10 тыс. знаков), вместе с «Проще» — не больше 40%; добавлен
  запрет общего с книгой куска длиннее 14 слов подряд — первая версия правила (треть, но
  не меньше 4000 знаков) дала конспекты коротких глав на 45–54% оригинала: это пересказ
  книги, а не опора для повторения, читатель главу уже прочёл — часть деталей главы
  живёт только в карточках и разборах вопросов, в конспекте их нет.
- Задача 3: добавлено правило 9: каждый файл главы есть в `content/files.js` — забытая
  строка оставила бы главу невидимой на странице — лишних отказов не даёт.
- Задачи 6 и 7: один коммит — обе правки переплетены в `app.js` — откатить по отдельности
  нельзя.
- Задача 4 идёт внутри задачи 8: пометки `kind`, род и вопросы-ситуации исполнитель
  вносит при сверке с книгой — тест всё равно переписывается под термины издания, две
  правки подряд одних вопросов дали бы двойную работу — задача 4 не имеет своего коммита.
- Задача 2: словарь охватывает и главы 3–5 — их авторы работают параллельно и не должны
  править общий файл — новые термины из следующих глав добавляет основная сессия.
- Задача 1: расхождения оглавления с приложением записаны в `docs/glossary.md`, а не в
  `docs/toc.md` — `toc.md` целиком пересоздаётся резалкой — искать их нужно в словаре.

- Задача 2: условие «каждый `term` приложения есть в словаре» выполнится только после
  задачи 8 — три термина приложения взяты из другого перевода, в словарь издания их
  вносить нельзя — до задачи 8 проверяльщик показывает по ним три замечания.
- Задача 2: для второго «голода» выбрано «Потребность в узнавании», а не «узнавательный
  голод» — так в определяющей фразе издания — три голода называются несимметрично.
- Задача 3: проверяльщику добавлены ключи `--only <id>` и `--grade` — главы пишут
  параллельно, недописанный соседний файл ронял бы проверку у всех; `--grade` сверяет

- Конвейер, шаг 7: один решающий вслепую берёт несколько глав подряд — ему нужны только
